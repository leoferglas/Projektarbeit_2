\section{Aktuelle Durchführung von Stichprobenanalyse im internal Audit bei Freudenberg}

Aktuell folgen die Stichprobenanalysen im Internal Audit bei Freudenberg einer strukturierten und risikoorientierten Vorgehensweise. Der Prozess lässt sich exemplarisch anhand der Prüfung von Lieferantenrechnungen ohne Bestellbezug beschreiben und ist grundsätzlich auf weitere Anwendungsfälle übertragbar. Zunächst wird eine Grundgesamtheit relevanter Objekte definiert, beispielsweise aller im Prüfungszeitraum erfassten Rechnungen ohne Bestellnummer. Anschließend wird diese Grundgesamtheit anhand definierter Kriterien, wie Rechnungswert, Lieferant, manueller Buchung oder weiterer risikorelevanter Merkmale, kategorisiert und analysiert.

Auf Basis dieser Klassifizierung wird ein Threshold festgelegt. Alle Rechnungen, die diesen Schwellenwert überschreiten, werden verpflichtend in die Stichprobe aufgenommen. Ergänzend dazu wird eine zufällige Auswahl weiterer Rechnungen aus der verbleibenden Grundgesamtheit getroffen, um eine angemessene Abdeckung des Prüffeldes sicherzustellen.

Die ausgewählten Stichprobenelemente werden anschließend durch den Auditor einer detaillierten Prüfung unterzogen. Hierbei werden sämtliche für die Bewertung relevanten Informationen und Nachweisdokumente gesammelt, geprüft und dokumentiert. Nach Abschluss der Analyse bewertet der Auditor die Ergebnisse hinsichtlich möglicher Auffälligkeiten, Abweichungen oder Regelverstöße. Werden Unregelmäßigkeiten festgestellt, werden diese dokumentiert und als Audit Exceptions erfasst.

Durch die Kombination aus risikobasierter Auswahl und zufälliger Stichprobenziehung wird sichergestellt, dass sowhol potenziell kritische Transaktionen als auch repräsentative Elemente der Grundgesamtheit in die Prüfung einbezogen werden. Dadurch kann mit vertretbarem Prüfungsaufwand ein hohes Maß an Prüfungssicherheit erreicht werden.

\section{Einordnung des KI-Einsatzes bei Freudenberg}
 
Die Freudenberg Gruppe nutzt aktuell gruppenweit die KI-Lösung von Microsoft Microsoft Copilot. Hierbei werden für alle Nutzer die Modelle GPT 4.5 und GPT 4.6 zur Verfügung gestellt. Der Copilot darf hierbei Zugriff auf alle internen Dokumente haben und bietet volle Datensicherheit- und integrität. Zusätzlich zum Microsoft Copilot gibt es für eine geringe Anzahl an Nutzern über GitHub Copilot die Möglichkeit auf begrenzte Ressourcen von Claude Sonnet und Claude Opus zuzugreifen. Hierbei liegte der Fokus jedoch auf der Software-Entwicklung. Die Anwendung auf den Auditbereich ist hierbei auf Grund von begrenzter Ressourcen nicht empfehlenswert.
